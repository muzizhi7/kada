# Agent Note: 终端接回任务后显示步骤与工具进度

Status: implemented

## Problem

长任务在后台执行时，终端通常只显示正在处理。用户重新接回后需要看到已做的步骤、当前操作以及待回答的问题。现有任务说明和交付结果已经落在 Pi 会话内，可以从相同记录呈现过程。

## Decision

运行时通过 Pi 1.4.0 的公开 LiveDoc 读取各会话正在执行的工具，向任务状态增加 activeTools。工具项保留稳定标识、工具名称和子 Agent 标记。运行和验收阶段展示活动工具，暂停、等待用户及终态返回空列表。任务视图通过 progress 暴露已有的步骤记录和工具名称。

终端的普通轮询、/attach 和 /status 使用同一进度格式。步骤和工具状态变化后才推送更新。步骤是 Agent 保存的辅助记录，任务的完成条件仍由既有验收路径决定。等待的问题参与更新判定，同一原因下更换问题也能显示。

## Alternatives considered

从历史工具调用推断当前工具可以减少一次读取。压缩、嵌套调用和并行结果需要额外判断调用是否已经结束。Pi 的 LiveDoc 维护当前工具状态，显示层使用这一公开投影。

让 Agent 每次进度变化都生成自然语言说明可提供更详细描述，但会增加请求和用量。当前显示读取既有步骤标题、等待问题及工具名称。

## Consequences

用户可以在终端接回任务并看到当前工作。精简任务接口增加 progress 字段，已有客户端可以按原字段读取。读取各会话的实时工具状态会增加状态查询的本地开销。工具参数和原始输出留在原有完整记录中。

验证使用真实本地 HTTP、Pi 会话、任务工具和终端会话逻辑，模型回复由脚本控制。覆盖步骤记录、工具参数隔离、重复轮询、终端接回、/status 以及等待用户时清除活动工具。在线模型判断质量和 macOS 客户端渲染另行验证。
