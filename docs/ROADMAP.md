v0.7.0已按后续生态方案收敛：新任务复用Pi1.4.0公开Skills加载/格式化API，人工与managed分离，取消专用学习工具和关键词匹配，保存并入已有提交；固定标准按编号核对。93项产品回归和原生入口联调通过，旧任务继续兼容。模型对照单列记录，不把格式迁移当成收益，试用学习继续默认关闭，详见[当前设计](learning-and-cost.md)。

v0.8.0按用户要求增加[首次启动环境发现](local-discovery.md)：已知Agent约定目录、标准Skills、插件/MCP元数据及少量偏好，普通本地缓存，按需原生读取；不加载外部插件运行时或扩大权限。提交前验证覆盖隐私边界、旧任务、刷新、真实模型、原生入口与干净安装，见[记录](verification-2026-10-31-discovery.md)。

## 0. 先验证颗粒度，再动运行层

- [x] 用已安装 Pi 1.4.0 的公开 API 做最小 hook 验证，覆盖自然答复结束、task_submit 终止、失败后继续、压缩和重启。
- [x] 确认 hook 与宿主只会有一处追加继续消息；记录请求 ID、提交和继续次数，恢复后不重复。
- [x] 明确现有宿主哪些职责能移到 extension，哪些边界仍需薄宿主；形成一个小的实现决定后再修改，不先整份重写 runtime.ts。

主要位置：[runtime.ts](../src/runtime.ts)、[goal.ts](../src/goal.ts)、Pi 文档与现有恢复测试。

退出条件：能用真实 Pi 机制演示“继续或交付”的单一路径及其恢复；不新增调度器、数据库、后台 Agent 编队或另一套任务机制。如果 hook 覆盖不了终止工具，保留该处现有薄边界，不以覆盖率为由扩建基础设施。

实测决定：自然答复能使用 onYield，主动终止工具绕过它；当前保留一处宿主检查/返工，不额外安装生产续跑 hook。机制测试使用脚本化模型、真实 Pi/SQLite/工具与 SIGKILL，不作为线上任务质量证据。

## 1. 先消除原型中的无效负担

- [x] 新任务不再因可选计划步骤未登记 done 而被退回；原定交付条件与用户要求继续有效。
- [x] 计划只在有帮助时保存阶段进展；修复次数与有无进展依据真实失败和产物，而不是 checkpoint 数量。
- [x] 修正累计压缩次数展示，清楚区分累计 token、缓存读取、费用与当前上下文。
- [x] 结束界面区分实际交付、通过的检查、失败和未核实部分；文件检查通过不自动表示完整质量通过。
- [x] 保持默认按需委派、无固定评审，不因为任务“复杂”就自动增加 Agent。

主要位置：[checks.ts](../src/checks.ts)、[goal.ts](../src/goal.ts)、[runtime.ts](../src/runtime.ts)、[chat.ts](../src/chat.ts)。

退出条件：同样的产物不再因登记缺失被无效返工；真正缺文件、数值错误或用户条件未满足时仍能继续修正。新增任务行为与旧任务兼容必须明确，历史配置/会话/产物保留。

## 2. 接上“明确目标 → 自主执行 → 有证据的交付”

- [x] 为模糊的新目标生成简短任务说明：交付物、必要输入、关键条件、授权范围、费用和时限；集中澄清影响结果的问题。
- [x] 复用用户已有明确指令与授权。确认后不因阶段转换、压缩或普通失败重新询问；超出范围或真实阻塞时说明具体原因。
- [x] 在 Pi 业务文档保留目标、关键要求、产物位置、当前检查与下一步。只保存需要的业务信息。
- [x] 先提炼少量可阅读的任务方法：数据/研究交付，批量资料处理。以 Pi 原生 read 按需读说明，不增加加载引擎。
- [x] 把现有命令/检查的真实结果关联到检查时的输入与产物。自检与独立核对分别呈现，关键条件不允许由执行者悄悄放宽。
- [x] 明确恢复时先检查文件、进程或应用状态，不盲目重放可能已经生效的外部操作。

退出条件：用户使用普通自然语言即可形成明确任务，确认后完成多个阶段；最终能追溯“什么交付了、依据什么检查、还有什么不知道”。不要求用户填写 JSON 或编写验收脚本。

研发回归使用已知汽车案例及其空值、零值、引用、报告数值不一致问题。检查方法要能识别正确结果与错误结果，不能把本次数据答案写入生产逻辑。对语义无法可靠判定的部分如实标明，不通过强行增加裁判 Agent 宣称已解决。

- [x] 比较实际交付、模型求助、内部返工、主/子/压缩总成本和恢复覆盖。
- [x] 复核评分器自身局限，导出去除本机路径的逐次数据。

- [ ] 有效小时级任务完成。一次CPU停滞命中60分钟时限只计取消覆盖；不能当作本项通过。

冻结新版行为后再做留出评测，不在运行中修改策略或喂评分反馈。开发回归不计作留出收益。

| 工作 | 设计 |
|---|---|
| 任务 | 6 个新任务，覆盖数据/研究、批量文件、已有代码项目；每类至少 2 个 |
| 条件 | Pi 加共同工具、Pi + 固定 Goal-Driven 模板、候选轻扩展；固定同模型、执行工具、Skills、权限和预算 |

| 验收 | 执行前固定全部关键条件；独立核对；人工语义复核尽可能隐藏方案标签，保留判断证据 |

必须报告完整交付数、实际人工消息、真实必要介入、误判完成、恢复中的重复动作、失败尝试成本和完整任务成本。没发消息但没达标仍是失败。不能用 90 分替代满足关键要求，也不能只展示有利的一次。

保留门槛见 [SPEC 第 6 节](../SPEC.md#6-实施顺序与验证门槛)：至少两个留出任务上有可重复收益，不增加错误完成判定；双方都成功的任务中，默认附加费用中位数原则上不超过 25%。这只是工程筛选，不能据小样本宣布统计显著。

退出选择必须允许三种结果：

1. 扩展策略有重复收益：保留对应最小模块。
2. 提示词/配置/Skill 已取得相同收益：按这些内容发布，收缩宿主。
3. 没有可重复增量：停止增加运行层能力，重新找真实缺口。

- [ ] 选两个有复用机会的任务族，固定原有质量检查与完整费用口径。
- [x] 在现有方法入口完成候选提炼、前提检查、版本固定和回退，不新建记忆或学习服务；11项专项测试通过。
- [x] 提炼沿用已确认预算，无有效发现时不增加固定反思调用，费用包含在Pi任务总额；试跑使用隔离开发序列，不动用户任务。
- [ ] 用新任务做学习关闭/开启及Pi参考；首轮目标为质量不退化、错误完成/用户纠正不增加，计入学习与失败后的合格交付模型成本降低至少20%。未达门槛不宣传优势，不回写旧实验。

已完成[三批54次开发试跑](experiments/2026-10-31-learning-results.md)，包含两个任务族与实际线上模型，估算USD0.4049。文件脚本在后两次新输入上实际复用；编程未提炼/加载方法。最终学习组比关闭组贵45.19%、比Pi参考贵20.53%，未达门槛，默认关闭；上项真正的新留出/用户任务验证仍未完成，不扩大自动学习。
