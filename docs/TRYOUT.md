# 小范围试用

本轮先看两件事：资料/文件能否完整交接，已有代码能否在保留原有约束的前提下修好。请用自己的真实工作副本，记录实际遗漏、纠正和费用。当前是原型，模型自检不保证语义正确，有效小时级和电脑操作仍未验证。

## 启动

需要Node.js24.7+。示例构建器需要Python3.9+；终端入口不要求Swift，macOS小宠物另需Swift命令行工具。

```sh
npm ci --ignore-scripts
# 首次配置；已有.env时保留原文件
cp .env.example .env
```

填写模型供应商、模型ID和自己的key。准备一个独立工作目录，放入资料或代码副本：

```sh
npm run chat -- --workspace /absolute/path/to/tryout-workspace
# 或在macOS运行可选的小宠物
npm run pet
```

在输入框说明目标、资料位置、必须保持的内容和预算。确认说明一次后，普通阶段不必发“继续”。命令型标准可以复用已有测试；自检和未验证范围会分别展示。真实阻塞或预算耗尽时需要处理，系统不会静默补钱。

## 两个试用目标

**资料与文件：**“把incoming里的资料整理成可交接的目录、索引和清单，保留原件及隐藏/空文件。需要转换的文件记录映射与处理结果，二进制不改字节。先说明怎样核对覆盖、遗漏、重名与失败项，再确认执行。总费用最多0.25美元。”

**已有代码：**“阅读项目说明、已有测试与这段缺陷描述，做最小修复，保留其他原行为。不要升级依赖或修改原有测试来凑通过。先提出允许修改的范围、原有核对命令与预算，确认后修改、实际运行并交付代码、变更和未覆盖范围。总费用最多0.25美元。”

已有核对程序放在工作区内；确认时可固定命令和需要保持原样的输入。待改源码、新生成测试和交付目录列为输出。没有独立核对时，报告会说明实际仅做了哪些自检。

固定整个输入目录也会核对成员增删。已有测试会写缓存时，先用项目支持的参数把缓存移到输出/临时目录或关闭缓存，并在确认说明中写清；不要把缓存写入误判为改测试，也不要为此忽略真实测试文件变化。

固定材料的[完整展示案例](../examples/handover/README.md)用于理解流程。判断实用性仍需要自己的任务，不能只重复示例成功。

第一轮可先邀请3—5位有真实资料或代码任务、愿意反馈具体错误的人。可转发：

> Kada 是一个基于 Pi 的目标驱动 Agent。它会结合现有工作环境，先与你确认交付和预算，再在后台推进，交回文件和实际检查结果。欢迎用一份资料或代码副本试试：哪些结果可用，哪里需要纠正，是否愿意把下一项工作交给它？先做小任务，自己设置费用上限；反馈时请去掉私人资料。

## 反馈记录

| 项目 | 请记录 |
|---|---|
| 原任务与关键要求 | 本来要交付什么，什么错误会让结果不可用 |
| 实际交付 | 哪些文件可用；缺失、错误或未验证的部分 |
| 人工介入 | 初次确认后补了几次信息、纠正了什么；是否不得不自己改文件 |
| 消耗与耗时 | 界面中的Pi估算费用、完成时间；失败尝试也保留 |
| 后续使用 | 是否愿意把下一项自己的工作继续交给它，原因是什么 |

遇到失败可记录任务ID、具体问题、相关文件及精简错误片段。分享前去掉私人内容；`.env`、本地配置、API token和SQLite会话不作为公开反馈材料。展示记录、小范围试用与开源发布分别推进。
