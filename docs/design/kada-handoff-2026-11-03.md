# Kada 交接栏：交互设计提案

2026-11-03。先使用 [oil-ui](https://github.com/oil-oil/oil-ui) 0.31.0 建立交接栏方向，在用户认可后，使用本地安装的 Oil UI Pro 0.23.8 深化。用户随后明确要求“就按这个设计落地到 Kada”；当前工作区已完成原生 AppKit/SwiftUI 实现，接入现有 Pi 对话、版本确认、预算和交付 API。该实现已进入主分支，尚未包含在 v0.8.0-alpha.1 下载包中；实现与本机加载验收见[原生交接栏验证](../verification-2026-11-03-handoff.md)。以下原型阶段的范围与验证保留为历史记录。

## 原生实施规范

- 用户已确认交接栏整体方向、视觉层级、记忆来源入口与安静执行/交付。本轮直接迁移，不再探索新方向。（用户确认）
- 样板代码在 `desktop/PetHandoff.swift`，共享颜色/按钮集中于该文件；原生输入继续使用 `PetInput.swift` 的持久 NSTextView，保留 IME 与光标。（前者为已确认设计的实现映射，后者为项目约束）
- 默认 420pt 内容宽度，外加阴影边距；高度按状态和实际答复/记忆内容收敛，并受当前屏幕约束。长约定和记忆在自身正文区滚动，费用与操作固定可见。320pt 内容宽度另行渲染核对。（Agent 实现判断）
- 字体、双紫 C6、辅助来源、单一主动作沿用已选样板；跟随系统浅/深色。用户已有自定义名字、图片和造型仍可选，不被强制改回 C6。（设计确认与历史数据约束）
- 记忆页通过带认证的只读 `/v1/environment/memory` 投影读取已有事实、引用、范围、待核实标记；不创建新存储或新模型循环。（Agent 实现判断）
- 预算修改提交给当前 Pi 准备会话，返回新版约定后用既有 revision/digest 确认。追加预算保留显式动作；数额和时限来自服务端的原有 resumeBudget。（既有业务约束）
- 收起条显示当前任务和状态，完成后更新“文件已就绪”，等待用户展开。错误、需要补充和预算阻塞保留可操作的恢复入口。（已确认设计）
- 主产物直接用系统应用打开，其他类型在 Finder 中显示；沿用原有路径/符号链接验证，不把脚本作为文档执行。（既有安全与文件语义）
- 动效采用按钮轻压、原生窗口 260ms 尺寸动画、首次角色与内容依序进入；减少动态效果时直接到位。（已确认设计的原生映射）
- 取证用独立本地 Pi fixture 和真实原生进程，不复制个人记忆，不发线上模型请求，不启用 computer-use 驱动。（项目约束）

## Pro 深化：当前样板与规范

本轮意图：已选方向内的 UI 整理与深化。用户“还不错”认可的是上一轮整体简洁方向；以下新细节均为 Agent 推断，待用户实际试用。原先的文件和预览保留，便于回看。

- 方向：交代一件事，执行时收起，完成后回到文件。保持小浮窗，不加用户背景问卷。（用户确认：简洁方向、直接认识用户；交接骨架为上轮已认可方案）
- 品牌资产：沿用已有 C6 紫/浅紫双模块、石墨面部、薄荷方眼，复用原生 drawKada 的矢量形状。（既有品牌约束，本轮不变）
- 字体与空间：SF/PingFang；正文 14px、辅助 13px、输入 16–17px、任务标题 22px。中性表面，主动作使用 C6 的紫色；来源和状态不靠微小文字表达。（Agent 推断）
- 共享语义：`--ku-ink/muted` 为正文/辅助，`--ku-surface/soft` 为浮窗/交互表面，`--ku-violet/on-violet` 为主动作，`--ku-on-mint` 为核验状态。320px 下按内容重排，不缩小整张窗口。（Agent 推断）
- 约定页：交付、标准、范围使用文字标签；费用与时限并排，完整保留含准备消耗、计时起点与追加规则。中文按语义换行。（Agent 推断）
- 交付页：主文件本身是打开入口，不再重复放“打开简报”。来源清单、核验范围和费用次一级。（Agent 推断）
- 记忆页：每条线索都可展开依据，项目规则标明当前项目范围，输入和附件返回后保留。（Agent 推断；来源约束沿用已有记忆实现）
- 安静执行：主动收起后，完成只更新小条为“文件已就绪”，等待用户展开，不自动抢回窗口。（Agent 推断）
- 动效：80ms 按下反馈，260ms 同锚点尺寸过渡、180ms 内容接替；首次 C6 先进入、内容晚 50ms。减少动态效果时直接到位。（Agent 推断）
- 新样板：线程预览 `kada-handoff-pro.html`；可复现包装页和证据在 `.oil-ui/kada-pro-2026-11-03/`。本样板的变量/样式是本轮取值依据，原生 `desktop/PetApp.swift` 仍待迁移。（Agent 推断，未改原生入口）

本轮删去约定页的重复引导、暂停页重复状态、交付页重复打开按钮，以及补资料页关于“目标会保留”的重复解释。费用规则、错误原因、资料范围与核验限制仍保留。

## 意图与范围

把一件事交给身旁的 Kada，然后回到自己的工作。

保留 C6 深紫/浅紫双模块角色、薄荷绿方眼和原生小浮窗。把视觉重心从问候标题与表单边框转向正在交代的目标；每个状态只有一个主要动作。没有新增常驻管理台、消息流水或用户背景问卷。

原型使用合成的“整理调研资料”任务、文件和费用；记忆视图中的条目用于展示来源结构。页面只在本地演示交互，不创建真实任务、不调用模型、不写用户记忆，也不读取选中文件的正文。

## 一件事的完整路径

| 状态 | 用户主要看到什么 | 主动作 | 次要动作与保留 |
| --- | --- | --- | --- |
| 交代目标 | C6、可直接输入的目标区、必要资料 | 交给 Kada | 添加资料、按需查看记忆；输入区轻基线明确可编辑 |
| 随口交谈 | 一次直接答复和继续输入的位置 | 发送下一句 | 问候、了解用户、偏好讨论不进入任务约定；交办具体工作后再展开约定 |
| 补充资料 | 一个影响结果的具体缺口 | 补充并继续 | 添加资料；保留原目标与已有附件 |
| 一次约定 | 完整交付、标准、范围、限制、费用与时限 | 确认并开始 | 调整后生成新版本；预算含准备消耗，时限从确认起计 |
| 安静执行 | 任务名称和实际状态 | 收起，等结果 | 可暂停；收起条保留任务与“展开”，不显示伪进度或工具流水 |
| 暂停或预算不足 | 已用费用、保留的工作和继续条件 | 查看追加预算 | 明确确认费用与时限后继续，不将普通“继续”做成暗中追加 |
| 收到交付 | 可打开的主文件与来源清单 | 打开主产物 | 新目标、按需展开核验范围与估算费用；自检与独立复核分开说明 |
| 查看记忆 | 具体工作线索及来源 | 回到当前工作 | 保留输入、附件和当前任务；没有背景问卷 |
| 连接中断 | 具体失败提示，原输入仍在 | 原地重试 | 不清空材料或伪造成功 |

从“目标输入—状态条—交付文件”保持同一个入口。原生实现继续用现有 NSTextView 和 IME 焦点机制，接回/恢复继续复用 Pi；本提案不改变任务、预算或历史数据语义。

普通对话路径对齐工作区的 `conversationInstructions`：问题直接回答，只有具体交付或持续执行才转成 Goal。原型仅用少量固定提示展示两种路径，不能把前端关键词判断作为正式意图引擎；正式判断仍归 Pi 同一会话。本轮没有改动这条正在进行的业务实现。

## 可见设计决定

- 380–420px 主体宽度；原型支持 320px 容器和 200% 等效重排，不另建手机产品。
- 中性表面、深色正文、单一紫色动作；色彩主要留给原有 C6。主按钮紧邻目标，不铺满外框。
- SF Pro Text / PingFang SC；输入 16–17px，正文 14px，来源/状态 12px。中文自然换行，重要内容不靠截断塞进固定高度。
- 外框 22px、动作 12px、附件 8px 圆角；仅在必要位置使用边界和分隔。不用大面积紫色输入底、光晕、装饰卡片或营销口号。
- 输入与记忆入口分工清楚，记忆视图保留来源，删除重复解释。关闭只收起，不承担取消任务。
- 按下立即反馈、状态切换约 260ms、首次轻量进入；C6 工作时收窄目光、模块对齐，完成后递出文件。减少动态效果时直接切换到位。

## 素材与实现映射

C6 图形复用 `desktop/PetApp.swift` 中 drawKada 的矢量形状与色彩，原型只为浏览器转写；没有生成新角色或更换品牌。产品参考查看了 Raycast 与 Granola 官网真实截图，借鉴主动作与内容层级关系，没有沿用它们的营销构图、字体和品牌色；没有把官网截图当成已经操作过其桌面 App 的证据。

正式实现时可映射到现有 PetBubble 状态和任务视图：目标/附件继续调用原提交入口，确认继续使用当前 revision/digest，资料调整通过既有消息更新说明，暂停/追加预算保持当前语义。原型的内联记忆视图尚需将适用的记忆摘要接入已有本机环境视图；现有原生菜单目前仍是打开本地记忆文档。本轮没有提前实现新的业务接口。
