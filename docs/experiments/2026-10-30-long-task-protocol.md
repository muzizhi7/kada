# 同一真实任务的三组对照

## 问题与任务

比较原生 Pi SDK、Pi 加 Goal-Driven 提示词、当前 v0.3 实现在一个多阶段真实本地任务上的交付质量、人工介入与用量。使用 OWID 发布的 IEA 2026 电动汽车数据和 IEA 原文，完成 2027 展望资料包：四表全外连接、八市场历史计算、统一公式的三情景、数据审计、引用索引、四张 SVG、中文报告、可重建脚本与测试。

完整要求在 [task.md](../../scripts/long-task/task.md)。输入为真实公开资料，不伪造异常或增加等待来拉长耗时。范围是数据处理与研究交付，不包含真实桌面、开放式实时检索或多小时无人值守压力测试。

## 固定条件

- Pi AI / durable 1.4.0；模型和所有子 Agent 均为 `deepseek/deepseek-flash`。
- 每组最高 45 分钟、估算 USD 1，无累计 token 硬限；相同 Pi 重试、120 秒请求超时、48k 当前上下文后台压缩配置。
- 同样的原始材料、任务与验收条件，逐文件 SHA-256。工作区独立，指令禁止读取其他组、试验评分器、配置和凭据。
- 统一根工具：read、write、edit、bash、delegate、task_status、task_plan、task_checkpoint、task_submit、task_blocked。子 Agent 统一使用四个原生终端/文件工具；最多三个并发。
- 为严格统一工具集合，原生组也装载共同的子 Agent 与任务状态薄接口。它是原生 Pi SDK 加统一工具壳，**并非 Pi 终端产品的开箱配置**；没有宿主的目标监督、自动返工或额外输入。
- 提示词组增加固定提交 `c8e54ba3e9a4cf65df8fd9d92d0f9b231cab7f45` 的 Goal-Driven 模板。替换 Goal/Criteria，并说明预算与共同工具接口。共同 delegate 是前台持久子会话接口，父 Agent 等待期间由 Pi 挂起，未额外实现/强制执行原文每五分钟巡检。评估的是这个提示词在共同工具接口上的实际行为，不是完整后台看门狗产品。
- 当前实现直接使用未修改的 LocalRuntime，review=false、web=false。其生命周期指令、自动检查和返工是被测差异；没有为本任务增强生产实现。
- 单次每组，顺序随机并记录。缓存、顺序和随机生成会影响单次结果，不据此宣称通用完成率或统计显著性。

## 介入记录

初始任务材料已确认，执行期间不补发“继续”、不修文件、不提供质量评分反馈。人类用户补充、评测员后续消息、程序内部返工分别记录；子 Agent 内部消息不算人工介入。

“实际没有发消息”不自动等于无人介入完成。若一组停下且独立检查不合格，记录为未完成，并标出至少需要外部纠正，不能用 0 次消息美化结果。用户信息请求另列。本轮不强制中断或额外续跑，因此不比较崩溃恢复优劣。

## 独立评分

机器评分器在执行前写好，原始任务和工具清单在首次模型调用前保存。评分器 SHA 与本说明在第一组运行期间、任何组结果产生前归档。全部组结束后才运行评分，不把结果送回试验模型。

| 项目 | 分数 | 检查 |
|---|---:|---|
| 标准化数据 | 25 | 完整外连接、键/值/缺失/代码与顺序口径 |
| 八市场历史指标 | 15 | 所有可用年份和同比/百分点计算 |
| 2027 三情景 | 15 | 24 行、公式、增长与占比限制、精度 |
| 审计与证据 | 10 | 机器 8 分：审计独立复算、引用结构；人工 2 分：四条 IEA 引用每条 0.5，核实实际支持 |
| 重建与测试 | 15 | 新目录重建 3、变更源值 3、缺失与真实零 3、重复拒绝 2、非法比例 1、NaN 拒绝 1、至少五项测试运行 2 |
| 报告 | 15 | 机器 8 分：结构/范围/图与来源；人工 7 分：数据口径与事实 3、反向观点和触发信号 2、完整可用分析 2 |
| 图表 | 5 | 机器 4 分：四份有效 SVG；人工 1 分：每张可读且年份/单位/比例与数据一致 0.25 |

合格交付要求：必需产物齐全，输入未变，标准化/历史指标/情景逐项正确，新目录重建通过，总分至少 90。其他缺陷保留明细。缺失文件与错误数值不能由报告篇幅、Agent 数量或模型自评替代。

机器评分从冻结原表独立计算。重建后再变更数据、制造重复或非法值属于**交付后的健壮性测试**，不是运行期间给某组增加困难。人工复核使用相同规则，非严格盲审，局限应披露。

## 用量与结论边界

从 Pi usage 汇总全部主/子 Agent 和压缩请求，报告累计 token、缓存读取、非缓存输入、输出、估算费用与耗时。累计 token 不等于当前上下文大小，缓存命中单列。价格采用本次 Pi 目录，不替代实际账单；异常流式请求的未返回用量可能无法完整计入。

优先判断是否在无外部纠正下合格交付，再比较消耗。能力保留只依据本案例能支持的证据：原生已有能力仍归 Pi；没有展示收益的额外策略不凭功能数量保留；单例不能排除它们在其他任务上的价值。

## 复现入口

1. 将四张 OWID CSV/metadata 和三篇 IEA HTML 下载到同一 sources 目录，保留下载链接。
2. `python3 scripts/long-task/prepare.py <资料目录>` 冻结输入与引用的 Goal-Driven 模板。
3. `npm run test:compare:long -- <资料目录>` 进行真实付费的三组执行，模板默认作为初始用户消息。`--prompt-system` 仅用于复现单列的系统指令预试。
4. 全部结束后审阅生成脚本，再用 `python3 scripts/long-task/grade.py <工作区> <fixture目录> --out <评分文件> --rebuild` 独立检查。
5. 渲染图表并复核报告与来源，填写人工 10 分，保存完整结果和限制。

原始资料、会话与 API 用量记录放在被 Git 忽略的 `.harness/benchmarks/`，公开文档只记录方法及汇总。

执行结果与本轮能力取舍见 [结果报告](2026-10-30-long-task-results.md)。最终汇总将“达到评分线”与“满足全部要求”分开；存在已发现的实质缺陷时，不能以总分超过 90 宣称任务全部完成。
