# 同一真实任务三组对照：结果与能力取舍

日期：2026-10-30。生产实现 v0.3.0 在执行与评分期间保持不变。

**本轮没有证明当前实现优于 Pi 基线。** 三组都连续执行、完成主要数据计算并生成全部文件，没有人工续跑消息；但独立检查发现三组都还存在实质缺陷。当前监督层触发的一次返工主要补记计划状态，没有纠正报告中的数值错误。Goal-Driven 正式组使用了两个子 Agent，消耗增加，本案例没有显示质量优势。

本轮评估的是目标和详细要求确认后的执行阶段。实际执行约 4—8 分钟，期间经过多次上下文压缩；这是一个真实、多阶段、上下文较重的任务，**不是多小时稳定性、崩溃恢复或完整需求澄清流程的证明**。

## 任务和对照条件

沿用用户的汽车行业研究场景，固定为“2027 汽车电动化展望资料包”：从真实 OWID/IEA 材料整理四表、计算八个市场历史指标、按指定公式生成 24 行三情景、数据审计、引用索引、四张图、中文报告、可重建 Python 程序与测试。历史数据截止 2025 年，2027 为任务机械情景，不能冒充机构预测。

四份 CSV 与元数据、三篇 IEA 原文在调用模型前冻结；四表全外连接应为 835 行，八市场指标 128 行。完整任务见 [task.md](../../scripts/long-task/task.md)，方法与评分权重见 [试验协议](2026-10-30-long-task-protocol.md)。

| 条件 | 三组共同设置 |
|---|---|
| Pi / 模型 | Pi 1.4.0；`deepseek/deepseek-flash`，包括所有子 Agent |
| 限制 | 每组 45 分钟、估算 USD 1；没有累计 token 硬停 |
| 工具 | 同样的 10 个根工具；子 Agent 同样使用 read/write/edit/bash，最多三个并发 |
| 上下文 | 同样约 48k 当前上下文触发 Pi 后台压缩；相同重试与超时 |
| 输入与权限 | 相同资料和验收、独立工作目录、同一本地用户权限；不访问外网或桌面 |
| 外部反馈 | 执行中不发“继续”、不修文件、不提供评分反馈；全部结束后才独立评分 |

**基线的准确含义：** 为满足“工具保持一致”，Pi SDK 基线也装载了共同的委派和 task_* 薄工具，使用同一压缩配置，但没有当前宿主的自动检查、返工或后续输入。它不是 Pi TUI 的开箱状态。因此本轮能比较提示词和宿主策略的增量，不能据此证明这些共同工具或压缩配置本身没有价值。

根工具 schema 的实际会话哈希一致：`0ad9d7e56d1aacb44d15aaf85cfaae1f34a3e9a562d55fb6048d95226251eb06`。生产 runtime、goal、delegation、execution、budget 源码与执行前记录的哈希一致。

Goal-Driven 使用[固定提交的模板](https://github.com/lidangzzz/goal-driven/blob/c8e54ba3e9a4cf65df8fd9d92d0f9b231cab7f45/README.md)，正式组将模板作为初始用户消息。共同 delegate 是 Pi 前台持久子会话，父 Agent 等待期间挂起；没有另建或强制原文的五分钟后台巡检。模型实际派出两个子 Agent，并由主会话参与执行，不能把结果称为严格复现“一主一从看门狗”。

## 执行、人工介入和消耗

| 正式组 | 耗时 | 累计 token | 子 Agent | 人工后续消息 | 宿主自动返工 | 估算费用 USD |
|---|---:|---:|---:|---:|---:|---:|
| Pi SDK 基线 | 4 分 21 秒 | 1,990,953 | 0 | 0 | 0 | 0.1391 |
| Pi + Goal-Driven | 8 分 17 秒 | 6,913,673 | 2 | 0 | 0 | 0.2761 |
| 当前实现 | 5 分 08 秒 | 2,501,294 | 0 | 0 | 1 | 0.1382 |

三组也都没有请求用户补充信息。“人工 0 次”是执行记录，**不是三组都无缺陷完成**；修复下面的问题还需要多少次纠正，本轮没有续跑测量。不能报告“无人值守完成率 100%”。

| 正式组 | 缓存输入 token | 非缓存输入 token | 输出 token | Pi 持久记录中的压缩次数 |
|---|---:|---:|---:|---:|
| Pi SDK 基线 | 1,728,512 | 206,867 | 55,574 | 3 |
| Pi + Goal-Driven | 6,419,584 | 394,842 | 99,247 | 5 |
| 当前实现 | 2,255,360 | 189,362 | 56,572 | 3 |

累计 token 包含多次请求反复携带的历史与缓存读取，不是一次上下文的长度。当前实现比基线多用 **25.6% 累计 token、18.3% 时间**，估算费用低约 0.6%；费用接近与缓存有关，不能宣布成本优化。提示词组累计 token 为基线约 3.47 倍、费用约 1.98 倍。单次运行和执行顺序会影响缓存与费用。

费用按本轮 Pi 模型目录计算：每百万非缓存输入 USD 0.30、缓存读取 0.006、输出 1.20，包含 Pi 汇总的主/子会话与压缩用量；不代替供应商账单，失败请求未返回的用量可能漏计。资料准备、实验编写与独立评分使用的 Codex 资源不在三组费用或执行耗时内。

当前实现第一次提交后，所有配置的文件检查已经通过，宿主只因七个计划步骤未标 done 而退回。Agent 随后重新执行构建和测试、写入七个 checkpoint、再次提交。约增加 22 秒、140,695 累计 token、USD 0.0204。它重新生成了数据文件，但没有修正文稿和空值处理；**这次自动返工没有显示交付质量收益**。

压缩次数来自遍历全部 Pi 持久记录。当前 CLI/status 的计数只覆盖当前可见的压缩标记，不能用来充当累计次数；本轮没有修改该生产展示逻辑。

## 独立质量检查

以下检查均在任务结束后执行，结果没有反馈给试验 Agent。不是直接采信各组写出的 checks.json。

| 检查 | Pi 基线 | Goal-Driven | 当前实现 |
|---|---|---|---|
| 原始输入哈希未变 | 通过 | 通过 | 通过 |
| 标准化、历史指标、三情景逐项复算 | 通过 | 通过 | 通过 |
| 新目录重建与变更源值重算 | 通过 | 通过 | 通过 |
| 重复键、非法比例、NaN 拒绝 | 通过 | 通过 | 通过 |
| 合法缺失与真实零的完整构建 | 通过 | **失败** | **失败** |
| 引用表约定接口 | **缺列** | **定量行 URL 不合约定** | 结构通过，分类有误 |
| 自带测试、四张 SVG 可解析 | 通过 | 通过 | 通过 |
| 报告人工核对 | **有实质错误** | **有实质错误** | **有实质错误** |

具体发现：

- **Pi 基线：** claims.csv 缺少规定的 source_file/source_locator/url 列；挪威情景说明写成 d=1.33、base=99.67%，与正确数据表的 d=2.667、base=100% 冲突；德国 31%→20% 被写成回撤 24 个百分点；把印度机械上限误读成“至少 38 万辆”；价格与供应链讨论不足。销量图中印度早期值落在绘图区下方。
- **Goal-Driven：** 输入真实零销量后，销量图调用 log10(0)，使整条构建失败；定量引用的 url 填的是本地定位文字；报告将原文“中国近 70% BEV 无补贴已便宜于燃油车”扩大为全球；将美国略降与 CSV 微增称为方向一致；图表有图例与来源文字重叠。
- **当前实现：** 拒绝本应保留的合法空数值单元格，自己的测试还把这种拒绝写成预期行为；摘要写美国 2027 base 为 2,121,191 辆、10%，后文及正确 CSV 则为 2,045,168 辆、11.53%；德国情景宽度被错写为中国的比例；历史事实误标 source_forecast。宿主验收和返工没有发现这些问题。

所有组的正确 CSV 都不意味着文字解释正确。三组均有至少三条反向观点、触发信号和方法限制，但仍包含过度因果判断。四组全部图表已经实际渲染检查，非只检查 XML。

评分线为机器 90 分 + 人工 10 分，总分至少 90 且关键数值/重建通过。它允许扣分，因此需要与“满足全部要求”区分。

| 正式组 | 原机器分 /90 | 格式语义复核后 /90 | 人工 /10 | 总分 /100 | 满足全部要求 |
|---|---:|---:|---:|---:|---|
| Pi SDK 基线 | 85.667 | 87.0 | 6.25 | 93.25 | 否 |
| Pi + Goal-Driven | 84.0 | 85.5 | 7.25 | 92.75 | 否 |
| 当前实现 | 87.0 | 87.0 | 7.00 | 94.00 | 否 |

不要将这些微小分差解释为能力排名。人工部分非盲审；本轮只有一个任务、每组一次。评分权重、数值参考和健壮性要求提前写好；评分器修正了合成输入清单的哈希，两版原分一致，见[评分器修正](2026-10-30-grader-amendment.md)。看到结果后还对所有组统一复核了两个机械格式代理：允许唯一可定位的文件简称，允许用“不能回答什么”表达风险/局限；原分保留，见[格式语义复核](2026-10-30-format-adjudication.md)。这是事后解释修正，不能声称全部评分过程完全预注册、结果无主观因素。

## 预试、限制与原始记录

最初将 Goal-Driven 放在 system/agent instructions，未按项目 Usage 作为初始用户模板。发现放置差异后，在任何独立质量评分前决定保留为预试，另跑正式提示词组；没有按质量选好的一次。详见[实施修正](2026-10-30-long-task-amendment.md)。预试耗时 12 分 28 秒，6,187,823 token，USD 0.2832，零人工消息、零子 Agent、六次压缩；机器 90/90、人工 7.5/10，总分 97.5，仍有印度增速、中欧差距方向等报告错误。**预试分数较高也完整保留，不用正式组覆盖它。** Pi 的 system sections 中能看到模板，不能说 Pi 丢失了提示词。

正式三组估算费用合计 **USD 0.5534**；包含预试合计 **USD 0.8366**。初始随机顺序为提示词预试→当前实现→Pi，正式提示词补跑在最后。没有重复采样或顺序平衡。

执行工具没有 OS 沙箱。除 Pi 基线外的执行也使用了 /tmp 临时文件，超出了任务中“只在工作区”的文字约束；日志未发现引用其他试验工作区，各次使用的临时校验文件由本次会话创建。不能把独立工作目录当成隔离保证。这限制了本轮可宣称的隔离性，但并未给某组额外工具或系统权限。

本轮没有测试真实桌面、混合应用操作、开放式实时检索、进程强杀、系统重启、长时间休眠或预算用尽恢复；独立评审默认关闭，不能据本轮判断评审 Agent 的收益。共同工具集合也限制了组件消融结论。

## 能力取舍

以下是本轮形成的方向决策，**尚未修改生产行为**。

| 能力 | 决策与依据 |
|---|---|
| Pi 原生执行、会话、压缩、持久化、基础恢复 | 继续直接复用。基线已无需“继续”跨过多次压缩；不要把这些机制当成项目自研卖点。恢复优劣另测。 |
| 任务费用/时间边界、累计/缓存用量展示 | 保留薄配置与展示；默认累计 token 硬停没有必要。本轮费用接近，未证明新增预算策略节省成本。修正压缩次数展示应列为小修。 |
| 目标、确认过的验收条件和交付物 | 保留最小业务状态。共同 task_* 工具没有单独消融，不能依据本轮直接删除。需求确认流程的效果仍待测试。 |
| 强制逐步 checkpoint、计划未完成就退回 | 简化。计划状态作为进度提示；是否完成以实际交付条件为主。本轮返工仅补状态并重跑已有检查，成本明确，收益未见。 |
| 自动继续/返工 | 保留为有具体失败证据时的薄策略，不扩成独立调度器；本轮不支持把笼统的“持续推进”作为已证实的竞争优势。 |
| 子 Agent | 按需，不默认固定主从或自动增员。提示词组两个 worker 更贵且仍有错误；单例也不能推出多 Agent 永远无用。 |
| 独立评审、computer-use、复杂恢复协调 | 保持可选/待验证，本轮未测；电脑驱动继续关闭，不安装、不请求系统授权。 |
| 与任务相关的真实验证 | 优先打磨。补小而可复用的检查/Skill：重建、边界值、引用语义、报告与数据一致性。优先采用已有工具，不建设通用评审平台；本轮评分器只是研究任务的独立验收样例。 |

当前最有希望的增量是：**把用户确认的完成条件变成能实际检查的证据，在具体失败后自动修正**。本轮显示的是这个方向的缺口，尚未显示我们已解决它。下一次实现应针对本轮真实漏检做最小改动，并用新留出任务重测；不要把这一个任务的答案写进通用运行逻辑，也不要先扩 Agent infra。

实验脚本与文档收尾验证：项目 typecheck、现有 35 项测试、run/inspect 脚本的独立 TypeScript 检查、全部评分脚本的 Python 语法检查、结果汇总一致性与文档本地链接检查通过。复现入口的提示词放置默认改为初始用户消息；历史执行脚本快照保留，未重新调用模型或改写试验产物来提高分数。
