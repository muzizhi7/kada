# v0.5.1 具体失败反馈：8次组件对照结果

2026-10-31。结论：**保留已验证的文件检查修复；自动反馈未显示重复的合格交付收益，不扩建运行层。** 按确认要求复核后，两组各合格交付2/4。反馈组另有两次宿主错误完成，无反馈组有两份合格产物被交付登记挡住。需要先减少人为交付障碍，并用真实业务检查发现缺陷，不能把更容易进入`completed`当作质量改善。

这是两题、每组两次的工程观察，不证明反馈普遍有害或有效，也不支持统计显著或“全球领先”。[执行协议](2026-10-31-feedback-protocol.md)、[逐次CSV](artifacts/2026-10-31-feedback/runs.csv)和[完整脱敏数据](artifacts/2026-10-31-feedback/results.json)保留失败、原始评分和敏感性复核。此前的[36次三类对照](2026-10-31-heldout-results.md)不重新计分。

## 1. 本轮实际修改与验证

v0.5.1只改现有路径，没有增加运行时、调度器、模型网关或评审编队：

- `Workspace.inspect`流式计算常规文件的原字节大小与SHA-256，交付检查和命令回执复用它；不再把大ZIP的存在性检查交给≤1MiB的文本读取器。
- 文本断言仍有独立大小/UTF-8/NUL限制；声明产物、文本检查和回执关联文件版本，改变文件后旧证明失效。
- 现有唯一返工边界返回有限条具体失败；命令失败含实际命令、退出码、错误预览，完整结果保存在任务状态。允许`maxReworks: 0`关闭自动反馈。
- 联网引用扫描说明不能读取的大文件/二进制范围，实际读取故障仍失败；没有新增通用二进制语义验证。

`npm test` **63/63**、`npm run typecheck`、`npm run build`通过；新增9项覆盖大二进制、空文件、原字节哈希、路径/符号链接、文件变化、真实失败回执、反馈开关和联网附带大产物。[修复验证](../verification-2026-10-31-artifacts.md)列出范围。

重放上一批真实6,151,739字节ZIP，原字节SHA-256为`245e7d819035e89dd9ef3e41d48ea25f2c53ee2bdd8358a5b91e38897c261311`：旧文件门槛失败，新检查通过，原件不变。**这是已知检查缺陷的回归修复**；原任务仍有独立命名错误，不将其改计成整体成功。

本地后台已安全重启到v0.5.1，7条用户任务和本地鉴权token保留，没有中断运行中的用户任务。computer-use继续关闭；这次没有改宠物界面，也没有进行新的视觉验收。

## 2. 对照范围

双方都使用同一生产LocalRuntime/Pi适配，唯一处理差异为`maxReworks=0/3`。原始数据沿用`pi`/`extension`标识，本文称**反馈关/开**。它们不是开箱Pi CLI和完整产品的比较；共同的确认、回执和提交门槛也不能从本实验推出收益。

| 固定项 | 实际配置 |
|---|---|
| 模型 / Pi / 本项目 | `deepseek/deepseek-flash` / 1.4.0 / 0.5.1 |
| 工具与指令 | 同11个根工具、4个可用子工具；规范化指令和工具schema哈希一致 |
| 执行 | 8次串行，重复内交叉顺序；已确认说明直接执行；无后续外部消息 |

| 压缩与委派 | 同48k阈值，实际共2次压缩、0个子Agent |
| 本批关闭 | web、真实computer-use、固定模型评审；无额外注入故障或延时 |

任务一使用[Click固定源码](https://github.com/pallets/click/tree/2247b35ea1c47c727d7a06e51fa280e12a863ff6)178个文件，另加7个声明的边界文件和1个内部符号链接。要求交付规范化树、185行映射、统计、说明和确定性STORED ZIP；检查真实二进制、BOM/换行、隐藏/空文件、跨目录重建和输入增删改。真实归档约1.76MB，不填充无关内容。

任务二使用[clsx固定源码](https://github.com/lukeed/clsx/tree/925494cf31bcd97d3337aacd34e659e80cae7fe2)，要求仅处理对象自有可枚举字符串键和数组自身索引，不读取继承getter，保留其他既有输入语义、导出及类型约束。两题均为本地拟定需求，不声称上游确认了同名问题。原始源码和许可证完整保留。实际运行Node24和TypeScript7，未运行真实旧Node或上游构建链。

初始批次因**我们提供的TypeScript入口遗漏`--ignoreConfig`**而统一作废：临时目录预检没有覆盖实际父目录tsconfig。3次结束、1次中断的全部原记录和费用保留；修正工具及预检位置后重新冻结8次，不按结果挑选，不使用外部评分来改模型答案。该工具修订意味着本批不是完全没有预运行的留出实验。

## 3. 原始评分与按要求复核

8次全部结束后先保存最终快照，再审阅生成程序，在临时副本执行独立检查。8个标签遮蔽条件后保存语义判断，再关联组别；同一编码助手设计任务及复核，**不是独立人类双盲**。本轮没有付费裁判模型。

固定评分器比较输出目录下的所有文件，误把一份不进ZIP的`.handover-build`本地标记也纳入跨目录字节一致性。它包含输出绝对路径，换目录后标记改变，但实际要求的规范化文件、清单、统计、INDEX和ZIP都相同。为此保留固定原分，同时对**全部四份文件任务**统一补做声明交付包的跨目录/重复/改输入/删除输入检查。只排除未交付的本地状态，不能豁免包内INDEX或ZIP变化。解释在汇总和条件揭示前记录。

5条反馈没有修复本批已发现的业务内容错误：文件题主要修提交清单，代码题修说明及自检状态。其中一条纠正了指向不存在文件的提交路径；它是交付清单修复，不是规范化数据质量改善。关闭反馈也不等于裸Pi原样结束：它仍被双方共同的提交门槛约束。

两个实质失败如下：

1. **代码兼容性：** 删除了原来的数组元素truthy判断。外部原行为探针期待`nested`，实际为`0 nested 0`。源代码也会把嵌套`null`送入`Object.keys(null)`。公共5项、自编11项和类型检查均通过，说明它们不覆盖该语义。模型仍声称保留falsey/nesting行为，宿主也判完成。
2. **归档跨目录复现：** 构建器默认目录在INDEX里写`incoming`，自定义输出写`<originals>`，导致INDEX和整个ZIP变化。同一目录重复构建、输入增删改检查通过，仍不满足明确的跨输出目录字节相同要求。最终说明承认这一差异，但任务标准没有允许豁免，宿主未识别。

另一个测量限制：clsx原有的宽`ClassDictionary`已经接受本批readonly正例，因此不将新增readonly别名计成被证明的新能力。类型检查仍检查导出、mutable ClassArray、string返回和未直接放宽成any等约束。

有效8次Pi估算费用合计**USD0.34952292**。作废批次记录USD0.16487586，两批已记录合计**USD0.51439878**；中断时未返回的请求可能缺usage，不能冒称最终供应商账单。为预算保护，已对中断尝试按整份USD0.25预留，两批保守预算占用USD0.748811272，低于USD2.25保护线。预留不是实际扣费。费用包含Pi的失败调用、压缩及所有实际会话；本次Codex开发/复核、本地CPU不计入该账本。

两组只有代码题第2次同时合格交付，其费用比0.5024；这个单一配对低于1.25，**不证明一般成本优势**。按执行前门槛：

- 至少两题重复合格交付改善：**0题，未达到**。
- 不增加已发现的错误完成：反馈组2次、控制组0次，**未达到**；不能据此断言反馈造成错误。
- 配对成功费用：仅1对，描述性满足，样本不足以推广。

所以不追加题目到出现有利结果，也不进入真实电脑执行阶段。这批执行约1.2—3.3分钟/次，没有验证有效小时级完成、恢复、开放搜索、需求澄清或宠物体验。

## 6. 保留与下一步

保留v0.5.1确定的原字节检查修复、有限真实错误信息、薄本地入口和Pi原生费用/会话能力。自动反馈开关保留兼容，现有默认仍为3；本轮不把它升级为已证优势，不默改用户配置或历史任务。

下一轮收敛应先处理两个明确缺口：**合格目录/空文件交付不应因为登记形式失败；状态写passed不能替代原行为/业务要求核验。** 先设计能保留证据与历史兼容的薄改法，复用现有项目测试和任务方法；不新增通用裁判、调度器或状态引擎。本轮尚未修改这两处门槛，不把路线图写成已实现。
