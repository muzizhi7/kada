# 三类真实任务对照结果与能力取舍

日期：2026-10-31。被测生产版本 v0.5.0，Pi 1.4.0。[执行前固定协议](2026-10-31-heldout-protocol.md)、[逐次数据 CSV](artifacts/2026-10-31-heldout/runs.csv)、[汇总与逐份复核证据 JSON](artifacts/2026-10-31-heldout/results.json)。

**当前实现没有达到预先提出的保留门槛。** 六个新任务、三种条件、各两次重复共 36 次，均已执行和复核。冻结严格口径下三组完整交付都是 2/12；纠正评分器对本地派生引用的过严要求后是 Pi 3/12、Goal-Driven 3/12、当前实现 2/12。当前实现没有出现同一任务两次均优于其余两组的完整交付收益，估算总模型费用为 Pi 基线的 2.00 倍。

据此停止增加运行层机制，保留 Pi 原生执行与用户需要的薄入口，把后续工作集中到已发现的交付检查缺陷及少量任务方法。这是一次工程筛选，不是三种方案的总体成功率排名，也不能据此宣传任一方案全球领先。

当前实现与 Pi **没有同一任务同次重复双方都完整交付的配对**，连引用修正口径也没有。因此预定的“双方成功时费用中位比≤1.25”是**不可评估**，不能拿整体 2.00 倍代替配对比，也不能把空配对算通过。

## 4. 真正暴露的缺口

### 4.1 自编测试可以完整复现错误理解

电力任务三个运行把所有年份的基数固定为 2014，报告与测试随之把固定基期变化称作同比。原表 Brazil：2014=590.55、2015=581.22、2016=578.89 TWh；2016 同比应为 **−0.400881%**，错误产物为 **−1.974431%**。两个候选运行都出现此问题，自称核验通过；另一个发生在 Goal-Driven。可重复的错误没有被目标/回执结构拦住。

其他研究产物出现年均差与 NOAA 年内增量算法解释不获来源支持、claims 最大差年份与正文矛盾、将最小发电国写成巴西却同时列出更小的英国。把表格从同一计算生成能减少抄错，但不能保证解释、主张和方法正确。

归档任务有三次把 `.git-blame-ignore-revs` 视为带扩展名，违背规范命名；另一次在只允许实体/CSV/JSON/INDEX 的 ZIP 内放入 restore.py。Markdown 一次按错误目录层级改写、一次遗漏标签中带行内代码的正常链接、一次猜测不存在的 `.html` 对应 `.md`。不能靠实体数量或压缩命令成功判定完整迁移。

### 4.2 核验还必须保护原有代码契约

QuickLRU 冻结机械探针漏掉了三个来自原要求的边界。语义源码复核后，对全部六份实现统一复现：有效 undefined 在代际切换中误调用工厂、修改旧 expiresIn 过期行为、`maxAge=0` 未命中返回 undefined 而非工厂值。三种错误分别出现在 Goal-Driven、当前实现、Pi；原机械成绩完整保留。

MRI 两个 Goal-Driven 运行机械行为通过；一个还把既有可写 Options 字段改 readonly，另一个仅把 unknown 回调返回类型从 void 放宽为 any。题目明确要求保留原类型，严格复核不接受；对“允许返回类型放宽”的敏感性结果单列。其余运行有负数位置参数被转成数字/旗标、布尔错误消费值，或时限前未形成交付。

因此需用现有项目契约、旧行为和针对需求的边界检查支撑验证。新增 Agent 数量或让执行者再写一遍独立脚本，不能自动构成独立正确性证明。

### 4.3 宿主存在可直接修复的错误检查

当前 `checkArtifacts` 对 `file_exists` 及声明产物也调用 `Workspace.read`，后者只接收 ≤1 MiB 的普通文本。真实 archive.zip 约 6.15 MB、library.zip 也超过上限，导致存在的二进制产物被拒绝、模型反复拆包/改验收路径，其中一次要求用户放宽限制。

这证明**检查范围错误会浪费预算并制造介入**，应优先修复为文件存在/大小/哈希与文本内容检查分别按其语义工作。此次相关归档/迁移产物本身也有关键缺陷，不能写成“已证明完整好产物被误拦截”。本轮严格定义下没有合格产物被宿主拦住的样本。

### 4.4 持久化与恢复属于 Pi 已有能力

MRI 六次都命中一次暂时工具失败。Markdown 六次计划强杀，实际五次在首份页面出现后 SIGKILL 并用原会话恢复；候选第二次未生成页面，没有触发边界。三组都已有恢复覆盖，但本题最终六份均未完整合格，不能把“进程恢复了”称为“恢复后交付正确”。

整批 66 次压缩、5 个子会话、5 次实际强杀恢复，无需用户续跑。免费准备校验也发现：外部写入已生效而回执未提交时，非幂等追加可能重放。Pi 持久化不等于任意外部动作恰好一次；应复用其会话，并在恢复后查看实际文件/状态。没有理由因此再造持久化、压缩、消息总线或调度器。

## 5. 评分器与结论的限制

保留原始评分，并明确这些后续解释；没有修改冻结评分器再覆盖成绩。

1. **引用格式过严。** 冻结检查要求每条 claims 有非空 URL、source_file 能解析为单个路径。但任务并未要求本地计算结果伪造外部 URL，也未禁止多文件证据。两份数值、报告和其他关键检查通过的电力产物，复核接受本地派生证据后分别为 Pi、Goal-Driven 各增加一次。复合路径的其他运行还存在实质错误，没有因此放行。
2. **有限代码探针。** QuickLRU 额外源码复现针对原要求，对全部六份同样执行。主表同时报告“机械通过”和“机械+语义通过”，不隐藏有利于任何一组的原成绩。MRI 的 void→any 解释也给出敏感性。
3. **Markdown 匹配口径。** 冻结正则会跨行匹配 HTML 标签，并把脚注体中的链接误当引用定义；最小相对路径与等价 `../pages/…` 也需区分。用统一保守单行范围排除脚注伪 URL 复核后，六份仍有清单/文本不一致；另外一些样本还有上述明确的真实链接错误。该题不适合单独用来证明某组优势。围栏相邻引用定义的另一个潜在问题，在原始语料和变更探针中命中数为 0。
4. **复核不是独立人类双盲。** 全部 36 份在揭示条件映射前保存判断，使用随机编号并渲染 12 幅 SVG；但同一编码助手设计任务、看过进度并复核，个别生成说明泄露过缩写运行路径，盲化不完整。透明 SVG 在某些 PNG 渲染器上黑底显示，未把渲染器背景问题算作品质失败。
5. **样本及范围有限。** 单一供应商/模型、六个编写的新任务、两次重复、统一预算，只能筛选工程方向。预算更大、其他模型或用户真实模糊需求可能表现不同；本批未验证开放搜索、computer-use、确认体验或有效小时级完成。共同工具/方法由各组共享，也未隔离单个模块的因果收益。

即使接受引用格式并放宽 MRI 返回类型，候选仍无新增合格交付，重复收益门槛仍不通过。不能用当前数据选择“Goal-Driven 已普遍优于 Pi”，也不能凭两个不同任务的偶然成功保留整套宿主监督。
