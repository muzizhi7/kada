# 办公与编程案例：冻结协议

本轮在 v0.8.0 上增加开发验证案例，不改产品执行策略。它检验实际交付与现有验证之间的差距，不能替代真实用户长任务试用，也不是行业评测榜。

## 案例与判据

| ID | 用户工作 | 关键语义与边界 | 交付 |
| --- | --- | --- | --- |
| office_reconcile | 采购、收货、付款对账 | 最新版本去重、退款、取消和孤立流水、零金额、按币种分别合计；换输入再运行 | 参数化脚本、3 张 CSV、说明 |
| office_minutes | 会议记录与后续更新整理 | 相对日期、乱序更新、完成/取消/阻塞、未明确负责人；不能恢复旧任务 | actions.csv、可读 DOCX |
| office_crm | 客户资料清洗 | 邮箱/电话传递合并、空键不合并、前导零、数值零、布尔 false、空值、错误行隔离 | XLSX、合并映射、拒绝清单、说明 |
| office_handover | 客户资料交接打包 | 同名文件、内容去重、二进制、空文件/目录、私人和草稿排除；换路径、增删输入和可重复 ZIP | 参数化脚本、ZIP、manifest、说明 |
| code_inventory | 修复目录清点 API | 递归、字节与 SHA、POSIX 路径、隐藏项、目录排除、符号链接与空目录 | 兼容原接口的源码、说明 |
| code_pool | 修复有界并发任务池 | 并发上限、顺序、同步异常、失败/取消停止派发、等待在途结束、监听器清理 | 源码、说明 |
| code_import | 修复 SQLite 增量导入 | 版本幂等、严格事务回滚、JSON 假值、非法记录、文本 ID、参数化 SQL | Python 源码、说明 |
| code_cache | 修复 HTTP JSON 缓存 | TTL 边界、深复制、请求合并、ETag/304、Accept 隔离、鉴权旁路、异常重试 | 源码、说明 |

输入全部为合成数据，中文内容、带空格路径和真实文件格式；无联网资料检索、电脑操作、真实账号数据或破坏性动作。输入及判据在付费执行前冻结。每个参考解必须通过公开检查和独立检查，每个案例至少两个故意缺陷必须被独立检查拒绝。独立探针位于工作区之外，不向执行 Agent 反馈；两个脚本案例另换输入执行，编程案例另建未见过的测试数据。

## 公平条件

8 个案例 × 两组 × 2 次 = 32 次。两次使用相同输入，检查随机性，不能当作 32 个独立任务。第 1 次 Pi 在先，第 2 次当前实现先执行。模型使用现有配置 `deepseek/deepseek-flash`；每次固定同一模型、工具、权限、USD0.08 / 5 分钟、最多一个可选同模型子 Agent，不固定增加 Agent/评审。

- Pi 参考组使用已安装 Pi 1.4.0 SDK，配相同业务状态、委派和验证工具，**不是未经修改的 Pi CLI**。不增加主任务监督循环。
- 当前组使用现有 LocalRuntime，目标监督、公开检查和自动修正照常启用。
- 两组均学习关闭、web/computer-use 关闭；相同重试和压缩配置。
- 两组的交付、输入和额度均预先确认；这轮不比较目标澄清质量或其费用。
- 相同的内置原生 Skill 和合成 `office-formats` Skill、发现清单；不使用真实 home 资料，不安装新驱动/软件。Skill 是通用格式提示，不含案例答案。
- 不发送人工继续或纠错消息。记录真正发出的人工消息和请求用户输入/阻塞的情况，不能把“没有回应请求”说成不需要人工。
- 全批保护额度 USD3。额度依据 Pi 已入账 usage，单个在途请求可能超过单任务阈值；失败及最后请求计入，不择优重跑。

## 结果口径

分别记录：产品/参考组宣告完成、公开检查通过、独立语义检查通过、原始输入保留。`qualified` 必须同时满足四项；`falseCompletion` 表示已经宣告完成但后三项至少一项失败。公开检查故意只覆盖部分规则，用于观察真实验证缺口，不能作为完整验收承诺。

报告每组总费用、总 token、缓存 token、模型响应次数、修正次数、人工消息和请求次数。费用取 Pi ledger 的全任务累计（含 worker、重试、压缩），不是最后一条响应；它是模型价格估算，不是服务商账单，不计本地 CPU。按成功交付分摊时保留失败费用。

DOCX 和 XLSX 另外渲染检查，记录页数、溢出和可读性；版式检查不被语义通过覆盖。办公摘要和代码解释仍有人工判断空间，自动探针不证明所有未来输入都正确。记录未执行的检查和渲染限制，不修补 Agent 产物以改变评分。

## 复现

Node 遵守项目 engines；Python ≥3.9。应用本身不需要 Python 办公依赖，只有这些开发案例需要 `scripts/cases/requirements.txt` 中的 openpyxl / python-docx。可在自己的 Python 环境准备依赖；不必改产品运行时或引入 conda。`CASE_PYTHON` 可为对照脚本指定 Python，Agent 仍须有同等可用的 python3 依赖。

```sh
npm run test:cases
npm run test:compare:cases
npm run test:compare:cases -- --execute
# 缩小为单类试验，仍需显式 --execute 才付费：
npm run test:compare:cases -- --cases code_cache --repeats 1
```

前两条不调用模型。对照脚本默认生成所有工作区并冻结材料，私有记录在 `.harness/office-code-studies/<id>`。它只复用 Pi 和已有对照辅助代码，不是新的运行时。原始 session/transcript 不提交；公开报告只保留合成案例的结果、费用和失败摘要。

## 检查器修订记录

本轮付费执行冻结的是 v1，8 个参考解与 16 个故意缺陷在执行前完成校准。结束后发现监听器清理判据约束了实现次数，统一纠正并增加并发边界，形成当前 v2：8 个参考解、19 个缺陷与一个无害重复清理控制。付费原始数据不覆盖，全部 32 份原产物做免费复核；[结果报告](2026-11-01-office-code-results.md)分列原始、纠正与补充口径，未来默认对照使用 v2。没有把补充结果称为事先冻结的主结果。
