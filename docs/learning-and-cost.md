# 任务方法自改进与成本下降

日期：2026-10-31。v0.7.0已把新任务收敛为Pi原生Skills薄适配，93项产品回归、类型检查、构建与原生小宠物联调通过。执行、会话、重试、压缩、恢复和费用仍由Pi1.4.0负责；默认不打开试用学习。研究依据见[Pi生态复核](pi-ecosystem-2026-10-31.md)。

## 当前实现：原生Skills与可选本地试用

新任务使用`@earendil-works/pi-coding-agent@1.4.0`公开的`loadSkills`和`formatSkillsForPrompt`。启动只提供名字、描述和路径；需要时以Pi原生`read`读取`SKILL.md`，通过原生工具执行相对路径脚本。没有关键词AND匹配、`task_method`、`task_learn`或固定结束反思。三份人工方法位于[skills](../skills/)，工作区可提供`.pi/skills/<name>/SKILL.md`；项目人工版本优先于内置版本，人工版本优先于同名生成版本。v0.8.0首次启动会[发现全局Agent与Skills](local-discovery.md)，只注入短概况和目录路径；完整目录/正文仍按需读取，避免全量常驻上下文。

借鉴Oh My Pi的人工/managed Skills分离：生成方法只放本机数据目录`skills/managed/`，不覆盖人工说明。只保留版本头、来源任务/回执与任务内固定快照；不新增语义检索、记忆服务或调度器。一个任务最多提供16个Skill，正文和资产按需读取；每个Skill至多16份UTF-8文件、合计128 KiB，单文件32 KiB，`SKILL.md`最多8 KiB。最多32个生成Skill、每个32个发布版本；超过上限跳过可选保存，不能阻塞交付。

实验开关仍是本地`harness.config.json`中的`"learning": true`，仅新建且经过一次任务说明确认的任务生效，不自动改用户配置。发现了值得复用的新脚本或工作步骤时，模型可在已授权的输出目录写一份标准Skill及脚本，**写完后再运行最终核对**，在已有`task_submit`的可选`skill`字段提交目录。没有发现、预算不够或旧方法已适用，就直接交付。此字段没有新增一轮模型调用，也不启动后台学习。

宿主先按原标准完成交付检查，再复用同一份新鲜的固定命令回执，确认Skill目录属于被核对的输出、原始输入与命令未变，然后保存为本地试用。缺少证据、无效格式、过大或过期时记录跳过原因，交付仍然完成，不让模型反复修可选提案。源任务通过并不证明该方法在未来更好或更便宜；新任务须重查格式、单位、环境、权限和当前交付标准。研究事实与引用必须重新核实，不能把旧结论作为通用答案。

全局版本变化不热换任务内快照。损坏版本会跳过；原生读取发现快照改变会明确失败。`SkillStore.rollback`可回到上一版本，无上一版本则停用；重新打开旧来源任务不会重新启用已回退版本。当前回退是宿主程序接口，没有新增宠物管理界面，也不把一次任务失败自动归因为Skill错误。实际读取记录不等于已采用，更不等于降低费用。

固定核对新增`task_verify({criterionId: 1})`，直接解析已确认的命令、原始输入和输出，执行前检查原始字节；额外自检仍可显式提供`command/inputs/outputs`。不能混填编号和自定义字段，不能用编号更换原标准。两种方式都继续通过Pi bash，不建立另一套执行器。

所有读取、写Skill、模型思考和失败都计入同一Pi任务总额。没有独立精确拆分混合响应中的学习费用；不把未增加模型调用写成免费。关闭学习仍有人工Skills，但不创建managed目录，也没有反思或候选调用。

验证命令为`npm test`、`npm run typecheck`、`npm run build`、`npm run test:pet`。对照免费预检：`npm run test:skills -- --offset 9`；显式付费执行：`npm run test:skills -- --offset 9 --execute`，24次开发样例、单次USD0.05、整批估算保护线USD1。各组共享模型和原生执行工具；关闭/开启/Pi参考共用编号核对，开启组只有可选提交字段及保存提示不同。v0.6组保留旧工具/核对schema作诊断比较；Pi参考是SDK加共同业务工具，不是开箱CLI。执行前统一预确认，未测澄清质量与费用。

本轮[24次同模型开发对照](experiments/2026-10-31-skills-results.md)已完成，估算USD0.181730880。原固定核对四组各6/6；事后按paid筛选后分组的零值审计中，精简关闭组5/6，其他组6/6。关闭总费用虽比旧实现低4.25%、比Pi参考低3.53%，不能据此宣称保质降本。开启比关闭贵28.16%，且未保存或读取生成Skill；这轮没有证明学习收益。保留原始与补充判据两种口径，学习默认关闭。

## 旧任务兼容与历史证据

v0.6任务继续按保存时的元数据、`task_method`、`task_learn`、关键词和前提文件处理，`learned-methods/`保持原样，不自动迁移为Skill；[learning.ts](../src/learning.ts)仅用于该兼容路径。新任务在元数据保存`resourcePolicy: "pi-skills"`。历史任务、凭据、会话和产物均保留。

此前54次开发试跑估算USD0.404926956。最终文件脚本复用两次，但学习组比关闭组贵45.19%、比Pi参考贵20.53%，未达门槛，见[旧报告](experiments/2026-10-31-learning-results.md)。约71%的费用增量来自未实际提炼/读取方法的代码任务，不能全部归因为提炼动作的直接费用。新格式不重算旧结果；本轮新对照单列记录，不能用已知开发样例代替新留出或真实用户证据。

## 目标与已有证据

让同一用户在相关本地任务中逐步积累有效方法，减少重新探索与返工，提高交付质量，并降低包含学习开销的合格交付成本。第一阶段覆盖资料/文件处理和代码修改。

当前没有成本优势证明。[36次既有对照](experiments/2026-10-31-heldout-results.md)中，候选总模型费用为Pi参考的2.00倍，且没有重复质量收益。该批任务已用于诊断，后续只能作为回归；新需求不改变历史结论。

本阶段的RSI指应用层执行方法的反复改进：Agent可以提出、测试并修订自己的工作方法，线上模型参数保持由供应商提供。效果依赖相似任务再次出现，不承诺每一单都更便宜或所有任务均优于其他Agent。

## 最小学习闭环

下列闭环是完整目标行为。当前原型实现源任务准入和后续试用/回退；独立新样例对照由开发脚本进行，尚未成为每次自动升级的内部步骤。

1. 执行真实任务，沿用已确认的目标、权限、交付标准和总预算。
2. 出现可复用的具体发现时，提出一项方法增量，例如有效脚本、环境探测步骤、数据口径或导致返工的错误。普通任务不固定加反思Agent。
3. 给候选写清适用条件、不适用条件、操作步骤、版本、来源任务与实际证据；保存方法和必要代码，不复制整份会话、密钥或研究结论作为通用答案。
4. 在资料/代码副本上，使用原有检查和未用于生成该方法的样例，对比旧方法或不加载方法的结果。新方法不能改低已确认标准、改核对答案或用自己的完成声明代替效果证据。
5. 有证据的方法进入试用；新任务按需读取。版本在任务开始时固定，同一任务中不自动热换。新版本不够好时保留旧版，有退化或前提变化时停用、回退或重验。

候选、试用版本、证据和停用原因用少量本地文件表示，不建设搜索服务、向量库或后台学习调度。能够自动核对且处于原授权与预算内的方法可自动试用，不要求用户逐条确认；依赖主观判断的改进保留未验证标记，利用正常交付反馈，不能自行宣布质量提高。

复用前检查前提，例如资料格式、项目根目录、工具版本、源文件与脚本版本。曾成功执行不代表现在还适用。时效数据和研究引用须按新任务重新获取或核验；复用计算与整理方法，不能把旧报告中的事实当成新事实。

## 学什么、怎样省钱

| 可改进内容 | 后续如何复用 | 需要观察的结果 |
|---|---|---|
| 资料与文件处理脚本 | 参数化输入输出，批量计算、转换、整理后仅向模型返回必要摘要 | 少读整份材料、少生成重复代码；结果与原始输入及核对一致 |
| 项目环境与编程步骤 | 复用已核实的根目录、依赖检查、构建/测试命令；修改前重新检查状态 | 少探索错误目录与命令，保留已有行为和新需求 |
| 具体失败与验证方法 | 相关任务提前检查已知边界；新检查作为原有标准的补充 | 相同错误与返工减少，不扩大错误完成声明 |

优先把确定性重复操作交给现有终端脚本，模型负责目标理解、例外处理和判断。方法只按需读取，限制索引与正文占用；不把所有历史经验加入每次系统提示词。继续复用Pi与供应商已有缓存、压缩和usage，不自行建立第二套机制。首轮不引入多模型路由，以便把方法效果与模型价格差异分开。

只有预计存在复用机会且额度允许时才提炼或评测候选；过大的候选、重复方法和无收益版本应合并或停用。首次提炼可能增加费用，长期节省必须覆盖这些费用。一次确认中的总预算覆盖执行、提炼、试跑与返工；额度不足时先交付当前目标，不在任务完成后暗中启动收费学习。

## Pi接入位置

已核对Pi1.4.0公开Skills类型/实现以及durable的Extensions、Tools、Your Own State和Usage and Cost。当前薄适配在[skills.ts](../src/skills.ts)，费用仍来自[budget.ts](../src/budget.ts)中的Pi usage汇总。

原生Skill加载复用官方coding-agent包；只调用其公开资源函数，不启动其CLI或第二个会话引擎。该官方包本身约25 MiB且带有上游依赖，这是复用公开API的安装体积代价，不能声称没有新增依赖。当前没有使用其TUI、MCP、codemode或图片处理运行能力。涉及发布或跨用户共享时另行整理；学习产物默认只留本机。

当前任务如需记录选中的方法版本与费用归属，使用Pi已有业务文档；候选评测复用现有对照脚本和Pi会话。完整运行、恢复、子Agent与压缩仍只有Pi一条执行路径。第一版经验只改变工作方法，不自动修改宿主源码、权限、预算、供应商配置或完成标准。

## 怎么证明有效

采用固定任务序列，分开发现/调试任务与新的留出任务。先比较同一实现的学习关闭/开启，关闭组保留相同的人工方法与既有功能；再与原生Pi加共同工具的参考组比较，明确适配差异。模型、输入、权限、工具、预算和原始检查保持一致。学习得到的文件是明确的实验变量，不把它暗中提供给关闭组。

开启组只能从当前及更早的已授权发现任务学习。留出轮开始前固定方法版本，禁止读取未来输入、评分答案或其他组执行轨迹；重复轮使用隔离副本并重置到相同起点。保留未加载任何方法、错误匹配、方法失败及停止的尝试，不只展示成功命中。

主要同时看两组指标：

- 质量：满足全部关键要求的完整交付、错误完成、实际用户纠正，以及相关缺陷是否复发。机械核对与语义复核分开，单个总分不抵消关键失败。
- 成本：所有执行、方法提炼、读取、试跑、压缩、委派、重试及失败费用；另列本地耗时、外部付费工具和缺失账单数据。分清Pi估算与实际账单，不能把无usage当免费。

固定序列的摊销模型成本 =（所有任务尝试模型费用 + 方法提炼/评测模型费用，按Pi会话或请求去重）/ 合格交付数。零合格交付记为无有效成本优势。分母变化必须同时报告质量，不能通过放弃难题取得优势。

同时给出不学习时的总费用、首次学习开销、后续命中费用与累计回本点。历史输入/工具缓存冷热与顺序影响单列；不能把缓存更热误认成方法学习。所有用户纠正和失败都保留，成功配对费用仅作补充。

首轮工程目标：至少两个新的任务族出现重复收益，完整交付不下降、已发现的错误完成和用户纠正不增加，且计入学习开销后的合格交付模型成本比关闭组和Pi参考均降低至少20%。这是一项待验证目标，样本小不能推出统计显著、普遍便宜或全球领先。未达标就缩减或移除无效方法；质量改善但更贵时据实归为质量策略，不宣传为成本优化。

## 实施顺序

- [x] 先从现有任务痕迹人工检查可重复的浪费，选资料/文件与编程各一个任务族，固定原始检查和成本口径。
- [x] 做一个候选方法的提炼、按需读取、前提检查、版本固定与回退，复用现有文件和Pi机制；不先建通用学习平台。
- [x] 在现有确认额度内包含学习开销，检查关闭学习没有额外模型请求、无候选时没有固定反思调用，目标交付不依赖学习成功；未独立精确拆分混合响应费用。
- [x] 完成三批开发序列的关闭/开启及Pi参考，包含不同输入与无匹配；过时前提由机制回归覆盖，完整费用和检查局限已记录，没有成本优势。
- [x] 收缩为原生Skills、取消专用学习工具/关键词匹配，精简提示并增加固定标准编号核对；旧任务单独兼容。
- [ ] 在真实用户任务与新留出任务族验证复用、过时前提及完整交付收益；当前开发序列不替代这一项。
- [ ] 达到门槛后才开启更多自动提炼，并逐步验证从旧方法改进到新版本的效果。小宠物继续只呈现目标、必要确认和交付，不增加训练操作面板。
