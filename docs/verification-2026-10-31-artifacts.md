# v0.5.1：交付检查与具体失败反馈

承接[36次对照](experiments/2026-10-31-heldout-results.md)发现的大ZIP误拒绝问题；继续使用Pi 1.4.0原生执行、回执、会话和恢复。

## 已实现

- `Workspace.inspect`对常规文件流式计算原始字节SHA-256和字节数，不受1MiB文本上限影响；与`task_verify`共用同一快照路径。
- `file_exists`要求工作区内常规文件存在，允许0字节；显式声明的交付产物仍要求非空字节。目录、路径越界和符号链接仍拒绝。
- `file_contains`/`json_value`通过独立的≤1MiB严格UTF-8文本视图处理，NUL/非法UTF-8不能被误当普通文本。哈希覆盖原始字节，包括BOM，而非解码后的字符串。
- 快照前后检查大小、修改/变更时间及路径指向；检查期间发生变化则失败。声明产物与文本断言不能拼接不同版本。这不是OS沙箱或全局原子事务。
- 大文件后续改变时，旧`task_verify`回执仍失效；在同一Pi会话重新执行检查，不补预算。
- 联网引用扫描遇到不支持文本读取的二进制/大文件，明确记录未扫描范围；可在交付摘要或受支持文本中引用已读取URL。文件丢失/读取故障仍是失败。此检查只证明访问与引用，不证明事实正确。
- 失败回执反馈含实际命令、退出码、错误预览和证明编号。自动消息最多展示6项、每项有限长度，完整结果可在`task_status`查看。继续仍来自现有唯一宿主边界。
- `maxReworks=0`可显式关闭自动反馈：首次核验失败记录`needs_attention`，不算完成；默认仍为3，负数无效。该开关用于组件对照，不新增生命周期机制。

已存任务、配置、密钥、会话和标准不迁移，已完成任务不因升级自动重算。存在性与非空文本的旧混用属于此次修复；文件存在/哈希通过不证明ZIP、PDF等格式内容正确。可选模型评审的旧只读工具仍以有限文本为主，未新增通用二进制语义阅读器。

## 验证

`npm test`共63项通过（原54项及9项新增），`npm run typecheck`与`npm run build`通过。新增回归覆盖：

1. 超过3MiB二进制的原字节证据与命令回执一致；文本断言仍受文本上限约束。
2. 空文件存在性、非空声明、中文/BOM、非法UTF-8/NUL的不同语义。
3. 目录、丢失文件、父路径及工作区内外符号链接继续拒绝。
4. 文件在产物快照与文本断言之间改变时拒绝混合版本。
5. 大文件旧回执失效、同会话重新核验、原预算与截止时间保持。
6. 真实命令退出7及具体断言进入失败反馈；反馈关闭时不追加消息。
7. 已检索并引用的研究答复附带大二进制时，不因文本上限错误退回。

最初一项测试把macOS临时目录的`/var`别名误作规范路径，改为工作区规范路径后通过；原字节哈希当时已正确。修正发生于模型对照冻结前。

新实验还通过3项免费评分器正反例、两组真实Pi/SQLite/工具的免费执行链路，以及实验TS脚本的单独严格类型检查。这些不是任务质量收益证据。

## 真实回归与组件结果

上一批真实6,151,739字节ZIP重放后，新文件检查通过且原SHA-256未变，旧检查失败；原任务仍有命名缺陷，只算文件检查回归。后台已安全重启至v0.5.1，7条用户任务与token保留，没有打断运行中的用户任务，电脑驱动仍关闭。

[8次组件对照](experiments/2026-10-31-feedback-results.md)已全部执行及复核。双方为同一生产Pi适配，仅自动反馈开/关不同，不是开箱Pi CLI。按声明包统一解释后的产物合格为关4/4、开2/4；宿主合格交付各2/4；固定原评分的合格交付为2/4、1/4，本地状态标记造成的评分范围过严和统一敏感性复核同时保留。反馈开组2次错误完成，关组2份好产物被目录登记挡住，没有达到重复收益门槛。

5条真实反馈主要修目录/路径/空文件声明与说明/状态，未解决本批发现的业务错误。当前显式声明仍拒绝目录与空文件，inspect仍要求passed；后续收缩尚未实施。有效8次Pi估算USD0.3495，含整批作废工具修订尝试已记录USD0.5144，中断未返回请求可能缺usage。不能因测试通过、错误信息更详细或多运行一轮就声称完成率提高。有效小时级完成和computer-use尚未验证。
