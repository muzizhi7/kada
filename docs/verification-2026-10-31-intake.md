# 目标澄清、一次确认与自主交付验证

日期：2026-10-31。版本 v0.4.0。完成 [ROADMAP 步骤 2](ROADMAP.md)，沿用 Pi 1.4.0；没有添加运行、模型或存储依赖。

## 已实现的用户流程

1. 新目标先进入同一个 Pi 主会话的只读准备阶段：可读文件、列目录、读取任务状态、保存任务说明。没有写入、bash、委派、联网或电脑操作工具。
2. 模型基于现有资料集中问最多三条实质问题；明确的要求直接复用。说明包含目标、交付物、输入、逐项标准、范围、假设、客观检查和总预算。
3. 说明就绪后，用户回复“确认开始”、简短同意，或 /confirm。客户端提交刚展示的 revision 与 digest，服务核对后才开放执行。文字含修改条件时作为修改请求，不模糊匹配为批准；旧说明的确认被拒绝。
4. 同一 Pi 会话执行、提交逐项标准结果、运行检查并修正具体失败。普通阶段、压缩、重启和返工不增加确认步骤。
5. 退出聊天会保留任务；未确认的任务等待，已确认的执行在后台继续。/attach 能接回待确认说明或执行状态。

已有明确授权可用聊天 /run、明确的“直接执行：”前缀、CLI run --yes，或 HTTP 创建时 confirmed=true，沿用配置预算直接执行。内部 SDK 的 LocalRuntime.create 默认保留已授权调用语义，需准备时显式传 prepare=true；公开 HTTP 默认进入准备阶段。历史任务不新增确认要求，也不批量迁移。

确认前的澄清请求沿用已配置费用/token 上限。确认说明的费用/token 是总额，包含澄清已用；确认不会把已用金额清零或额外赠送同额配额。执行时限从确认开始，等待用户不扣执行时间；之后离线时间计入时限。重复确认和重启都不补预算，/resume 才是显式补充一次已确认预算（历史/直接执行任务沿用配置）。

## 实现颗粒度

- [preparation.ts](../src/preparation.ts)：只读工具集合、任务说明与预算、当前说明摘要。使用 Pi configure 切换选中的 extension。
- [goal.ts](../src/goal.ts)：在已有 GoalDoc 增加可选说明、确认和证明字段；目标、标准和进展仍由 Pi commit 持久化。确认与续跑 outbox 在一次 Pi 业务提交中记录，不创建新的数据库或任务队列。
- [runtime.ts](../src/runtime.ts)：在原有边界核对确认版本、预算和逐项交付；确认后配置原生执行工具，再复用已有 outbox/requestId 续跑。重开根据保存的确认状态选择工具，不能由模型自发切换权限。
- [verification.ts](../src/verification.ts)：task_verify 薄调用 api.executeTool("bash")，保留实际退出码、输出尾部、输入前后及产物哈希。不增加另一套命令执行器；不把嵌套工具 usage 再转发计费。
- [任务方法](../methods/README.md)：数据研究和批量文件工作的两份普通说明，由原生 read 按需读取，没有新 Skill 加载器。

准备阶段只选择只读工具，不是 OS 沙箱。确认后 Shell 仍使用本地用户权限；外部文件里的指令不能扩展授权。电脑驱动仍关闭。

## 如何检查交付

确认后的标准使用稳定的 1-based ID。提交时每项必须提供 passed/failed/unverified 与证据；遗漏、失败、未核实或未知标准 ID 会被退回。

命令型标准必须引用有效 task_verify proof ID。回执来自实际 Pi bash；退出失败、检查时输入变化、或交付时输入/产物已变化都不能通过。修改文件后需要重新核验。回执最多保留最近 32 项；task_status 默认只返回摘要，指定 proofId 可读单份详细回执，减少反复携带输出和哈希。

内容型标准是 Agent 的具体自检，界面与命令核验、独立模型复核分别呈现。一个检查程序也可能写错，退出码/哈希不能证明所有事实或语义正确。标准分类和检查方法本身的质量仍需通过后续留出任务验证。

## 自动与恢复测试

完整测试 **53 通过、0 失败**（此前 42 + 新增 11），另外通过项目类型检查、构建与新测试/worker/联调脚本的严格 TypeScript 检查。最后修正列表接口的执行时限投影后，8 项准备流程回归、类型检查与构建再次通过。独立临时数据目录中的离线 demo 也通过，原有双子 Agent 与可选评审流程保持兼容。

新增覆盖：

- 必要信息澄清后确认一次，同一会话自动修复错误结果、独立重算并提交逐项证据。
- 确认前写入工具不可用；执行后不能改写说明；新版本使旧批准失效。
- 等待、暂停和重开不等于确认；时限从确认开始，重复确认不补配额。
- 澄清 token 消耗保留；已用量超过所提议上限时不能确认。费用策略测试在 Pi 自有 ledger 注入已知费用，不实际计费。
- 旧回执对应的产物改变后被退回；检查即使退出0，只要改变声明输入也不能通过；诊断来自实际命令输出。
- 聊天 /attach 恢复说明、只确认已展示版本，已有授权可走直接执行入口。
- HTTP 默认只准备，普通 messages 不能制造批准；缺失/过期摘要及错误 confirmed 类型被拒绝。
- 在未确认与已执行两个阶段分别 SIGKILL；前者重启仍等待且不发模型请求，后者保留确认、预算、proof ID 和已完成追加，不重复动作。

测试见 [preparation.test.ts](../test/preparation.test.ts)、[preparation-recovery.test.ts](../test/preparation-recovery.test.ts)、[worker](../test/fixtures/preparation-worker.ts)与 [server.test.ts](../test/server.test.ts)。其余原有压缩、委派、预算、旧任务和评审恢复测试继续通过。自动测试使用脚本化模型、真实 Pi/SQLite/文件/命令/进程。
