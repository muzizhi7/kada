# 本地方法试用闭环验证

日期：2026-10-31，代码v0.6.0，Pi1.4.0。范围见[专项设计](learning-and-cost.md)。本轮实现与机制测试通过；质量和摊销成本优势须由真实任务另行证明。

## 实现

- 只对新建、开启`learning`且已确认说明的任务开放两个薄工具。`task_learn`提出一项候选，`task_method`通过Pi原生read读取固定版本，或报告失败回退。
- 候选绑定当前通过的确认命令、原始输入与输出；脚本必须在已核对的输出中。完整交付通过后才发布为本地试用，未通过的任务不发布。
- 关键词须实际出现在源目标中；至多提供两个匹配方法。文件前提变更、无关目标、损坏记录跳过，任务中固定旧版本。
- 版本更新保留上一试用版本；失败后回退/停用。重复恢复不会覆盖新版本，也不会重新启用已停用版本。
- 没有固定反思模型、额外执行循环或新服务。提炼尝试失败后不要求修复可选提案；模型即使再次调用也不会重新提炼。原任务的交付条件保持原样。
- 学习成本包含在原Pi任务总额中；混合响应不精确分摊为单独学习费用。方法使用记录只是总任务费用的引用，不能重复相加。

核心位置：[learning.ts](../src/learning.ts)、[runtime.ts](../src/runtime.ts)、[goal.ts](../src/goal.ts)、[budget.ts](../src/budget.ts)。

## 机制与回归

`npm test`：82/82通过。其中11项学习专项覆盖真实Pi/SQLite/原生命令执行链路：

- 原任务提炼脚本，后续不同输入复用已保存字节并完成原始检查；保留一次确认。
- 关闭学习无新工具、无额外模型请求、无方法目录；无发现的任务没有强制提炼或反思。
- 虚构证明、过期证明、未核对脚本、越界前提与无效匹配词不能形成可用方法；提炼失败不阻止交付。
- 目录私有权限、记录损坏与前提变化跳过、失败回退、重开保持任务版本与原预算。
- 候选已保存但任务交付失败时不发布；报告方法失败后仍可完成当前目标。
- 一个可选提炼尝试失败后，第二次调用被跳过，不产生宿主返工。

类型检查、构建、对照脚本与专项测试的严格类型检查通过。

`npm run test:pet`：54项原生核心核对、12项输入连续性、6项名字/造型流程、实际退出重开与一次确认到交付联调通过。原生测试不用线上模型。记录：`.harness/pet-tests/a2727310-35ab-48e9-a58b-8463ea53184d/`。

## 实际收益与限制

对照使用隔离开发样例和既有线上模型，不修改用户历史、配置或凭据。每批执行前冻结生产代码、任务方法、资料和原始核对；中途不改方案或给模型评分反馈。学习开启组增加两个方法工具，其他执行工具一致；Pi参考为SDK加共同业务工具，不冒称开箱Pi CLI。

学习开启不等于实际提炼/使用，方法读取也不自动证明优于原方法。代码任务的固定检查可能遗漏原要求，另做合同边界复核并保留原成绩。最终费用与取舍见[开发试跑结果](experiments/2026-10-31-learning-results.md)。

当前仍默认关闭学习。现有运行中的用户后台与小宠物不会被测试脚本自动重启；使用v0.6.0需客户端/后台同版本。开启配置只影响后续确认的新任务，既有任务不迁移。
