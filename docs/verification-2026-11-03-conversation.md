# 普通对话按需进入 Goal：实现与验证

日期：2026-11-03。该轮验证时为尚未发布的工作区增量。调整源于最近一次简单背景交流被建为 Goal：宿主把正常答复判为没有任务说明，连结束语也触发返工并等待确认。

## 当前行为

- 终端、桌面新对话使用 `mode: "chat"`，仍由原 Pi 1.4.0 会话执行、持久化、压缩和恢复。普通问答、简短文本、记忆交流及结束语直接答复，不创建 `GoalDoc`，不执行 Goal 交付检查或未提交返工。
- 只读材料、联网查询及 `user_remember` 可用于普通对话；记忆引语来自 Pi 的真实用户条目，读取和整理记忆不再隐含建立业务目标。命令、写文件、委派仍在确认后的任务工具集中。
- 现有模型通过同一会话中的 `task_prepare` 按需提出实际交付任务。有效说明在 Pi 同一原子提交中初始化 Goal，之后继续使用原来的版本确认、累计预算、执行和验收；任务列表显示实际任务目标。
- 不新增分类模型、独立 Agent、会话日志、运行时、调度器或数据库。普通会话费用/token 沿用累计限额，闲置时间不计入下一轮执行时限；只有显式 resume 补配额。
- 不带 mode 的显式任务 API、`run`、`/run` 及历史任务保持既有语义；历史会话没有被迁移、重新确认或重新执行。已进入 Goal 的任务后续仍按原任务流程处理，新普通对话使用“新对话”或 `/new`。
- 原生窗口直接投影 Pi 的最近普通答复，继续显示输入框；普通回答不展示预算确认卡。客户端核对 `ordinary-chat` 后台能力，避免同版本旧后台忽略 chat 参数。

已核对安装版 Pi README 的 Extensions、Tools、Per-Conversation Agent、Your Own State、Persist and Resume，以及 `snapshot`、原生 entries、工具终止和 configure 的公开类型/实现。`snapshot` 不创建缺失的业务文档，恢复和提交去重继续使用 Pi。
