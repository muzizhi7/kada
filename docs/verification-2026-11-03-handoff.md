# 原生交接栏：实施与验证

2026-11-03，实施当时的工作区增量。用户确认 Oil UI Pro 交接栏方案后要求落到 Kada；本轮把原型迁入真实 AppKit/SwiftUI 客户端，未将演示意图判断、费用或文件内容带入产品。

## 当前实现

- `PetHandoff.swift` 集中原生视觉变量、按钮、输入布局、交付约定、记忆页及收起条。内容宽度 420pt，短答复、编辑、记忆和交付按内容收敛高度；长约定正文滚动，费用和确认动作保持可见。跟随系统浅/深色，继续保留用户的名字、C6/旧造型与自定义图片。
- 原生 NSTextView 继续承接中文组合输入、选区和焦点。切换记忆时保留目标和资料；连接或提交失败保留输入，支持重试。普通问题直接呈现现有 Pi 答复，实际任务才进入约定。
- 总费用和执行时限可在约定页调整。客户端通过现有消息接口请 Pi 更新说明，不自行改 Goal 或制造确认；只有新版 revision/digest 的显式确认才开始。暂停后的追加额度和时限仍来自服务端原有 resumeBudget，打开说明不等于恢复执行。
- 收起后显示任务及状态，完成只更新“文件已就绪／查看交付”，等待用户展开。主文件直接打开；复用既有产物路径、符号链接、目录与可执行文件处理。没有文件的文字交付直接呈现真实摘要，不显示空文件页。
- 内联记忆调用带认证的 `GET /v1/environment/memory`，只投影已有活跃记忆、引用、适用范围和待核实标记，不返回整份来源文档。来源变化后不展示过时事实，关闭 discovery 时不读取记忆。没有新存储、调度器或模型循环。
- 按钮轻压、首次角色/内容依序进入、窗口 260ms 尺寸切换已接入；减少动态效果时直接到位。没有自动安装电脑驱动或请求系统自动化/录屏权限。

增加能力前核对了安装的 Pi 1.4.0 的 Extensions、Tools、Persist and Resume 与业务状态文档。模型接入、会话、压缩、恢复、确认、预算和执行继续复用现有路径；本轮增加的是只读投影与客户端呈现。

## 调试中发现并修复的问题

初次原生测试出现堆内存破坏。Guard Malloc 将非法访问定位到窗口尺寸动画：通过 `PetPanel.animator()` 代理调用最终 Swift 子类中带实例计数的 `setFrame` 覆盖不安全。改为 AppKit 的 `setFrame(_:display:animate:)`，接收者保持真实窗口，尺寸时长由 `animationResizeTime` 提供。修复后 Guard Malloc 全链路和重开通过，记录在 `.harness/pet-tests/bfc72fcd-866a-4d0c-b73e-d3fea3e438ce/`；上述三次正常启动验证均在修复后完成。

失败尝试和中间渲染保留在各自忽略目录，不作为通过记录。旧命令行工具的 Address Sanitizer 拦截器不能初始化，该尝试未用来宣称内存验收；有效内存保护记录来自系统 Guard Malloc。输入控件拆除时也清除委托与回调，避免切换状态后残留输入连接。
