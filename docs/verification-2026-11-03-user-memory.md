# 主动认识用户与工作记忆：验证记录

日期：2026-11-03。此项在本轮验证时尚未发布；没有重启既有后台、发布版本或扫描开发者真实个人资料。

## 本轮行为

首次后台启动在原有能力发现之外，自动读取约定的用户指导、USER.md 和已有 Agent 记忆，生成分类摘录、来源证据与可读用户记忆，不新增背景问卷。当前启动分类按标题与原文进行，不调用模型。

相关新任务获得短记忆和按需读取路径。语义整理和明确纠正通过 `user_remember` 在原 Pi 准备/执行会话内完成；工具需要实际来源摘录，项目记忆不提升成全局偏好，已有 Agent 记忆保持待核实。子会话没有全局记忆写入工具。没有新增运行时、模型路由、数据库、向量索引、调度器或后台学习 Agent。

新增文件：`src/user-memory.ts`、`test/user-memory.test.ts`。发现与任务装配分别在 `discovery.ts`、`runtime.ts` 中衔接；CLI 和原生菜单可查看记忆。Pi 复用点已核对本机安装 1.4.0 的 README 中 Extensions、Tools、Your Own State 与原生 read API。

## 验证结果

- `npm run check`：类型检查、121 项产品测试、构建及提交候选检查全部通过。新用户记忆测试 8 项，没有线上模型请求。
- `xcrun swiftc -typecheck -parse-as-library -target arm64-apple-macosx13.0 ...`：整个原生桌面应用类型检查通过；既有测试辅助字典仍有类型推断警告。
- 临时目录编译并运行 `PetCoreTests`：61 项核心检查通过，包括旧后台没有 memory 字段时的解码、新记忆路径的独立解码。临时二进制和测试资料已清理，没有打开或替换运行中的用户窗口。
- 补充样例复现并修复 JSON 引号包围的凭据字段未被省略、YAML 元数据后紧接标题导致分类标题丢失的问题。
- 最后兼容性补充：关闭发现/暂不可用时仍返回 memory=null、memoryFacts=0；CLI 兼容旧后台缺少新字段。相关发现与记忆测试重新核对。

八项新增测试覆盖：

1. 无模型启动、从指导正文形成分类记忆、原文哈希、作用范围、原件不变和私有文件权限。
2. 来源修改/删除后的过时标记、原来源追溯、跨来源分歧保留和重启复用。
3. 常见凭据/私钥省略，不读取会话/凭据文件，跳过越界链接、二进制和超限文件。
4. 拒绝伪造出处、模型编造用户引语、项目提升为全局、旧 Agent 记忆改标明述和任务中失效的摘录。
5. 用户自然给出的明确纠正可替代旧记忆，工具重复执行不产生重复事实。
6. 损坏的派生记忆可重建，原用户材料保留。
7. 真实 Pi/SQLite 路径完成准备、整理记忆、确认、执行、子会话边界与交付；重启后第二项任务直接获得整理结果，不增加背景询问。
8. 原元数据发现任务恢复时保持原上下文和工具，不追补新记忆能力。

## 实际范围与待验证项

全部材料来自隔离的合成用户目录，Pi、文件、SQLite 与工具路径是真实实现，模型答复是脚本化的。这里证明链路、来源约束、历史兼容与重启行为；没有评估真实模型能否准确提炼偏好，也没有证明任务质量提升或成本下降。

自动读取范围和上限见[本机发现与用户记忆](local-discovery.md)。复杂自然语言分歧仍由当前任务实际阅读材料判断，程序不充当通用语义裁判；常见凭据过滤也不能保证覆盖所有秘密格式。没有首次认识问卷，没有真实 computer-use，任务确认、模型、预算与历史数据语义保留。
